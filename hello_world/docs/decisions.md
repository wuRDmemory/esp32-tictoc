# 需求决策记录

本文档记录 **voice_notes 项目在做需求澄清时的每一个决策，以及支撑它的证据**。

**为什么单独记这个**：这些决策将来一定会被重新问到（"当初为什么选 16k 不选
48k？"）。没有依据的决策会被反复讨论；有依据的决策一句话就能结案。

记录格式：**决策 → 依据 → 备选方案为什么没选。**

---

## D1 · 术语：这是 STT 不是 TTS

| | |
|---|---|
| **决策** | 项目按 **STT / ASR**（语音→文字）实现，TTS（文字→语音）不在范围内 |
| **依据** | 用户四条需求（收音、流式转写、总结、按键）全部指向语音转文字。原始表述「TTS 转写工具」中 TTS 一词使用有误 —— TTS 是反方向 |
| **确认过程** | 已向用户当面确认「最后要不要读出来」，用户明确回答**不要，纯转写+总结** |

---

## D2 · 采样率：16 kHz / Low-Power 模式

| | |
|---|---|
| **决策** | 16 000 Hz，运行在芯片的 Low-Power 模式 |
| **依据 1** | 数据手册 Table 5 的采样率范围有**空档**：Low-Power 是 6.25–18.75 kHz，High-Performance 是 23–51.6 kHz。**16 kHz 只存在于 Low-Power 模式**，不是可选项 |
| **依据 2** | 高性能模式带来的收益几乎为零。Table 3（Low-Power，**标定条件就是 fS = 16 kHz**）SNR 64 dBA / EIN 30 dBA SPL；高性能模式 SNR 65 dBA / EIN 29 dBA SPL —— **只差 1 dB**。手册自己也写着 "high SNR and 120 dB SPL AOP in **all** operational modes" |
| **备选：48 kHz / High-Performance** | **没选**。理由：只多 1 dB SNR，却要付三倍数据量、一次降采样（引入自身伪影）、翻倍功耗（230→490 µA）。且 48k 不是 ASR 的原生输入 |
| **附带确认** | SCK = 64 × 16 000 = **1.024 MHz**，落在手册 400 kHz–3.3 MHz 范围内 |

---

## D3 · 板子只采音，不做识别

| | |
|---|---|
| **决策** | ESP32 固件只做「I²S 采集 → 打包 → 传输」，ASR 与总结全部在 PC 上 |
| **依据** | ① 经典 ESP32 算力跑不动可用的中文 ASR；② ASR 想升级模型时，改 PC 比重新烧固件快得多；③ 用户要的两个未来变更点（换传输、换 ASR）都在 PC 侧 |
| **备选：`espressif/esp-sr` 板端识别** | **没选**。识别率低、模型固定、且会把固件变成难以迭代的巨石 |

---

## D4 · 传输：串口与 WiFi 两条都做，共用帧格式

| | |
|---|---|
| **决策** | 实现 `AudioSource` 抽象，下挂 `SerialSource` 和 `TcpSource`，**二者共用同一套帧格式** |
| **依据** | 用户明确要求「两条都实现」。共用帧格式让传输层可互换，是 `AudioSource` 抽象成立的前提 |
| **实现顺序** | 串口优先（阶段 2），WiFi 后置（阶段 5）—— 串口链路已在 hello_world 阶段验证过，零新增风险 |

### D4.1 · 波特率 921600

| | |
|---|---|
| **决策** | 串口从 115200 提到 **921600** 8N1 |
| **依据** | 净荷 32 000 B/s，加 1.4% 帧头 = **32 938 B/s**。921600 8N1 净速率 92 160 B/s，占用率 **35.7%**，有 2.8 倍余量 |
| **为什么不能用 115200** | 115200 净速率 11 520 B/s，**装不下** 33 KB/s —— 差 2.9 倍，会持续丢帧 |
| **退路** | 921600 不稳就退 460800（仍有 1.4 倍余量） |

## D5 · 显示：终端

| | |
|---|---|
| **决策** | 转写与总结都渲染在终端 |
| **依据** | 用户选择。终端最快能跑通，也最容易调试 —— 流式问题在终端里表现为滚动文本，比在浏览器里更容易看清时序 |

## D6 · 不做 TTS 播报

| | |
|---|---|
| **决策** | 最终产物是文字，不合成语音 |
| **依据** | 用户明确选择「不要，纯转写+总结」。范围最小、最快落地 |
| **保留** | 架构上在 `Summarizer` 后面留了位置，将来要加 CosyVoice 播报不用重构 |

## D7 · ASR：本地优先，但留云接口

| | |
|---|---|
| **决策** | 实现 `AsrProvider` 抽象，先做本地 `FunASRProvider`，云实现留空 |
| **依据** | 用户选择「先本地跑通，留好云 API 接口」 |
| **直接收益** | **用户不需要申请任何 API key** —— 不注册、不实名、不充值、音频不出本机 |

### D7.1 · 本地引擎选 FunASR 而非 faster-whisper

| | |
|---|---|
| **决策** | `paraformer-zh-streaming` |
| **依据 1** | 需求 #2 明确要求「**流式**输出，实时显示」。FunASR 的 paraformer-streaming 是**真流式**（逐块增量输出）；faster-whisper **不是流式模型**，只能用 VAD 切段后整段转写，属于伪流式 |
| **依据 2** | 中文原生优化（阿里达摩院），16 kHz 单声道正好是它的原生输入，与 D2 的选择天然吻合 |
| **依据 3** | 流式参数明确：`chunk_size=[0,10,5]` = 600 ms 块 + 300 ms lookahead —— 延迟可预算（见 NFR-1） |
| **备选：faster-whisper** | **没选但保留**。它的"伪流式"有个体验问题：**已经显示出来的字会被后续块改写**。这不是 bug，是整段重转写的必然结果，但看起来像在抽搐 |
| **切换成本** | 两者都在 `AsrProvider` 后面，换实现不改下游 |

---

## D8 · 总结：本地 ollama，滚动重总结

| | |
|---|---|
| **决策** | 用本地 ollama + `qwen2.5:7b`，录音中每 **20 秒**把**至今全文**重新总结一次，停止时出定稿 |
| **依据 1** | 用户原话「对于**所有内容**重新进行总结」—— 指向滚动重总结，而非只在结束时总结一次 |
| **依据 2** | 用户选择本地 ollama（不引入第二个 API key） |
| **参数** | `temperature = 0`。否则每次刷新结果都在抖，屏幕上看起来像在乱跳 |
| **实现约束** | **必须后台线程**。7B 总结一次 2–3 秒，同步跑会把转写显示卡住 2–3 秒，直接违反目标 G1 |
| **现状核实** | 已实测 ollama **当前未运行**（11434 端口无监听），需要 `ollama serve` + `ollama pull`。已列为用户待办 4.1 |

## D9 · 按键：延后到阶段 6，先用串口命令

| | |
|---|---|
| **决策** | 阶段 2–5 用串口命令 `start` / `stop` 触发；物理按键在阶段 6 接入 |
| **依据** | 用户选择「先不管按键，串口命令代替」。按键是**交互层**，与音频链路正交 —— 先把它排除，能把阶段 1 的风险暴露得更干净 |

### D9.1 · 按键行为：按一下开始 / 再按结束 + 静音兜底

| | |
|---|---|
| **决策** | Toggle 模式，外加「静音 5 秒自动结束」兜底 |
| **依据** | 用户确认。Toggle 适合长场景（会议记录），不会像 PTT 那样手一松就断；静音兜底防止"忘了按停" |
| **代价** | 中间停顿超过 5 秒会被提前切断 → 所以阈值必须现场标定（风险 R9） |

---

## D10 · GPIO 分配：22 / 25 / 26

| | |
|---|---|
| **决策** | WS→GPIO25，SCK→GPIO26，SD→GPIO22 |
| **依据** | 必须避开三类脚：**GPIO 6–11**（SPI Flash，碰了必死机）、**GPIO 0/2/12/15**（strapping，上电电平决定启动模式）、**GPIO 1/3**（UART0 console，占了就看不到日志） |
| **备注** | GPIO 25/26 兼作 DAC，但本项目不用 DAC，可安全用作 I²S |
| **按键（阶段 6）** | 推荐 GPIO 27（空闲、无复用冲突、非 strapping） |

---

| | |
|---|---|
